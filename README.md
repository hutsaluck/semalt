# AI Radar

Каталог AI-інструментів для розробників, дизайнерів, авторів контенту та людей, які автоматизують повсякденну роботу. Тестовий проєкт для Semalt.

Пошук за задачею, шість категорій, мінімальний DR, три сортування, сторінки по 20 результатів, деталі в діалозі та локальне обране без реєстрації. Увесь службовий інтерфейс українською; назви й описи джерела залишені оригінальною мовою.

**Виправлення CORS від 03.10.2026:** FreeSerp повертає два `Access-Control-Allow-Origin: *`, через які Chrome блокував прямий fetch. Тепер браузер звертається до `/api/freeserp` на тому самому сервері, що й застосунок: Vite пересилає запит реальному FreeSerp у dev/preview, а Netlify — через правило в `public/_redirects`. Пошук перевірено в Chrome без тестового перехоплення: `html` і `dog` повертають реальні результати. Це необхідне відхилення від початкового прямого підключення, щоб каталог працював за некоректного CORS джерела. Фікстури не використовуються у каталозі. Докладні результати — у [звіті](docs/test-report.md).

## Встановлення та запуск

Потрібні npm і **Node.js 22.12+ у гілці 22, Node.js 24 або 26+**. Точний діапазон — `engines` у package.json. Перевірено з Node.js 22.12.0 і npm 10.9.0. `.nvmrc` фіксує перевірену версію. Python 3 потрібен лише для повторного пакування ZIP; запуск застосунку від нього не залежить.

```bash
npm ci
npm run dev
```

Відкрити `http://127.0.0.1:5173/#/`. Для перевірок і production preview:

```bash
npm run lint
npm run typecheck
npm run test -- --run
npm run build
npm run preview
```

Preview за замовчуванням працює на `http://127.0.0.1:4173/` і також має API-проксі. Якщо dev/preview був запущений до зміни конфігурації, перезапустіть його та оновіть вкладку браузера. `dist/index.html` потрібно відкривати через HTTP-сервер, а не подвійним натисканням як `file://`. Звичайний статичний сервер на кшталт Python http.server показує сторінки, але для каталогу має також обслуговувати `/api/freeserp`; для локального перегляду використовуйте `npm run preview`.

## Технології та структура

React 19, TypeScript 5.9, Vite 8, React Router 7 з HashRouter, звичайний CSS, fetch, lucide-react; Vitest 5 та ESLint 9. Версії зафіксовані в package.json і lock-файлі. Версію typescript-eslint підібрано без залежностей, що потребують Node.js 22.13 замість доступного 22.12. ESLint 9 має повідомлення npm про завершення підтримки; наступне оновлення інструментів варто робити разом з оновленням Node.js та перевірками сумісності. Перевірка npm audit не виявила відомих вразливостей на момент роботи.

```text
src/api/          fetch, помилки, валідація відповіді й кеш
src/components/  пошук, картки, діалог, навігація, стани запитів
src/hooks/       запити каталогу та контекст обраного
src/pages/       каталог, обране, опис проєкту
src/types/       нормалізовані типи
src/utils/       URL-запити, нормалізація даних, localStorage та тести
src/styles/      адаптивний інтерфейс
docs/            план, журнал роботи, звіт та докази перевірок
scripts/         створення архіву
```

Логіка застосунку й обране залишаються клієнтськими: ключ, акаунт і база даних не потрібні. Єдина серверна операція — пересилання фіксованого API-маршруту засобами наявного Vite або хостингу; окремого бекенду й нових залежностей для цього не додано. HashRouter та `base: ./` дозволяють розміщення інтерфейсу в підкаталозі без SPA rewrite-правил. API-маршрут `/api/freeserp` завжди розміщується в корені цього ж origin.

## Інтеграція FreeSerp

[Документація](https://freeserp.ai/docs.php), [машиночитаний help](https://freeserp.ai/api.php?help=1). Endpoint джерела: `https://freeserp.ai/api.php`; endpoint браузера: `/api/freeserp`. Вбудований [проксі Vite](https://vite.dev/config/server-options.html#server-proxy) та його [preview-конфігурація](https://vite.dev/config/preview-options.html#preview-proxy) пересилають лише цей маршрут до фіксованого FreeSerp, зберігаючи query-параметри. Кожний запит має `index=sites`, `ai_startups=1`, `order=desc`, `size=20`, `from`. Обов’язкові параметри не залежать від користувацького URL.

```text
/api/freeserp?index=sites&ai_startups=1&sort=dr&order=desc&size=20&from=0
→ https://freeserp.ai/api.php?index=sites&ai_startups=1&sort=dr&order=desc&size=20&from=0
```

`q`, `ai_categories`, `dr_min` передаються лише з непорожніми значеннями через URLSearchParams. Пошук, фільтри, сортування й пагінація виконуються API. `from + size` не перевищує 10 000; за виходу за фактичну кількість сторінок URL повертається на першу сторінку. Категорії з `&` кодуються коректно. Фактичне значення для асистентів — **`AI Chatbot & Assistant`**, хоча docs.php називає його `Chatbot & Assistant`; live-запити підтвердили перший варіант. Help підтверджує параметр і приклади, але не перелічує повну таксономію.

Пошук має debounce 400 мс, Enter запускає його одразу без дублювання. Запити скасовуються AbortController; застаріла відповідь не змінює поточну видачу. Таймаут 15 секунд охоплює fetch і читання JSON. Обмежений кеш у пам’яті: TTL 5 хвилин, до 30 успішних відповідей, ключ — усі API-параметри. Після перезавантаження кеш зникає. Повтор після помилки обходить кеш і кеш браузерного HTTP-запиту.

Окремі типи помилок: HTTP, `ok: false`, невалідний JSON, некоректна структура, таймаут, мережевий збій. Інтерфейс показує зрозумілий текст; скасування не стає помилкою. Проксі не генерує відповіді каталогу: помилка FreeSerp або недоступний маршрут дають відповідний error state. TLS-перевірка лишається ввімкненою; cookies браузера не додаються до fetch.

Дані перевіряються під час виконання: DR=0 зберігається, відсутній DR не замінюється нулем, некоректна дата ховається, описи мають fallback. Записи без валідного домену пропускаються; якщо вся непорожня відповідь невалідна, показується помилка структури. Зовнішні URL допускають лише http/https, без облікових даних і стороннього домену, та нормалізуються до головної сторінки. API-текст відображається як текст React. Немає повних текстів сайтів, обходу зовнішніх сторінок чи сторонніх favicon-сервісів.

## Сторінки та обране

- `/#/` — каталог; `q`, `ai_categories`, `dr_min`, `sort`, `page` у query частині hash-маршруту. Типові значення DR і першої сторінки опущені. Налаштування переживають reload і Back/Forward.
- `/#/saved` — локальна добірка з мінімальними snapshot-записами для карток і деталей. Ключ `ai-radar:favorites:v1`, дедуплікація за нормалізованим доменом. Пошкоджене або недоступне сховище не ламає застосунок; невдалий запис супроводжується попередженням. Вкладки одного браузера узгоджуються через `storage`.
- `/#/about` — призначення, сценарій, джерело даних, пояснення DR і дати та обмеження.

Повний [план сайту](docs/site-plan.md). Обране існує лише в цьому браузері; очищення localStorage видаляє добірку. Деталі використовують завантажені дані, підтримують Escape, Tab/Shift+Tab та повернення фокусу.

## Перевірки та робота з AI

56 автоматичних тестів охоплюють параметри й кодування, пагінацію, нормалізацію, обране, помилки, таймаут, скасування, кеш і використання маршруту того самого origin. Окремо виконано браузерні smoke-перевірки dev/production preview з реальними запитами через проксі, без перехоплення відповідей.

Перші перевірки 02.10.2026 використовували тестове виправлення заголовка Playwright; їхні історичні результати збережено окремо. Після виправлення 03.10.2026 каталог і пошук перевірено у звичайному Chrome через Vite без такого harness. Помилки, затримки, недоступне сховище та крайні стани перевірено контрольованими фікстурами. Фікстури не імпортуються застосунком і не потрапляють у його збірку.

Фактичні результати, команди й обмеження: [test-report.md](docs/test-report.md). AI прочитав ТЗ, дослідив контракт, написав код, тести й документацію та виправив проблеми за результатами перевірок. Конкретний журнал: [ai-workflow.md](docs/ai-workflow.md).

## Публікація й передача

Деплой не виконано, публічного демо немає. Підготовлено `dist/`, конфігурацію `netlify.toml` та правило API-проксі `public/_redirects`, яке Vite копіює у `dist/_redirects`.

За [актуальною інструкцією Netlify для Vite](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/) налаштування: команда **`npm run build`**, папка публікації **`dist`**. Після окремої авторизації на публікацію можна підключити репозиторій у Netlify або завантажити готову папку `dist` через інтерфейс майданчика. Для збірки встановити сумісний Node.js; `netlify.toml` задає перевірений 22.12.0. Hash-маршрути не потребують rewrite на `index.html`. Правило `/api/freeserp https://freeserp.ai/api.php 200!` використовує [вбудований проксі Netlify](https://docs.netlify.com/manage/routing/redirects/rewrites-proxies/#proxy-to-another-service); [query-параметри передаються далі](https://docs.netlify.com/manage/routing/redirects/redirect-options/#query-parameters). Воно міститься в dist, тому доступне й для ручного завантаження збірки. Конфігурацію перевірено за документацією; живий Netlify-деплой не тестувався. Після публікації перевірити `/#/saved`, `/#/about`, ресурси та `/api/freeserp`.

Готовий архів: **`ai-radar-submission.zip`**. Усередині папка `ai-radar/` із кодом, lock-файлом, public, docs, конфігураціями й dist. Для повторного пакування:

```bash
npm run build
npm run package
```

Скрипт використовує явний список файлів, виключає node_modules, .git, IDE, секрети та сам архів, перевіряє цілісність ZIP.

## Обмеження та подальший розвиток

Для каталогу хостинг має підтримувати фіксований API-проксі: Vite локально або правило Netlify в підготовленій збірці. Просте копіювання dist на довільний файловий хостинг без такого маршруту недостатнє. Категоризація та описи FreeSerp можуть містити шум, неповні дані й не гарантують AI-функцій кожного результату. DR — авторитетність домену, не користувацька оцінка; «Виявлено онлайн» — не запуск продукту. Пошук залежить від мови й формулювання в індексі: `собачки` дав 0 результатів, а `dog` — 235; порожня видача є коректним результатом, не CORS-помилкою.

Не реалізовані реєстрація, бекенд, база даних, адмінпанель, чат, платежі, переклад описів, порівняння та нескінченна прокрутка. SPA без пререндерингу не заявляється як повністю SEO-оптимізована. Lighthouse та окремі прогони Safari/Firefox не виконувалися. Наступні невеликі поліпшення: оновлення інструментів після оновлення Node.js, перевірка контракту при зміні API та ручний аудит із допоміжними технологіями.
